# 기능설명서 v2 · 심사 관점 검토와 편집 결정

2026-09-16. 사용자의 상세 피드백과 기존 13쪽 전수 시각 검토, 실제 구현 코드, 공식 양식/제출 매뉴얼을 대조했다. 앱 기능을 새로 구현하거나 운영 배포를 변경하는 작업은 아니다.

## 심사자가 읽을 때의 문제

1. 공통 양식 제목과 넓은 항목 열이 본문보다 먼저 보인다. 서비스 설명은 기능명·사용 목적·결과의 위계가 약하다.
2. 430×900 캡처를 280×279 칸에 맞춰 넣어 실제 화면 폭이 약133px이었다. 화면 속 수치·버튼을 읽기 어려웠다.
3. 4개 화면 나열이 순서만 보여주고 사용자의 입력·변경 결과를 설명하지 못했다. 같은 비교 화면도 반복됐다.
4. API 빈 행과 작성일/내부 검수 문구가 미완성 자료처럼 보였다. 기타 데이터 설명은 활용보다 경고가 강조됐다.
5. 차별성/발전계획이 같은 크기의 긴 문단으로 이어졌다. 현재 구현과 향후 검증의 관계가 보이지 않았다.

## 최종 편집 방향

- **공식 표지·섹션명·필수 작성 항목 보존.** 본문 배치와 글꼴을 재설계한다. 매뉴얼은 항목 누락/변경을 금지하며 원본 흐름도 슬라이드는 필요 시 복사할 수 있다. 글꼴과 4열 구조를 고정하라는 조건은 확인하지 못했다.
- **총16쪽, 핵심 기능5개.** 일정 작성, 여유 조정, 공개 제안의 복잡한 단계만2쪽으로 나눈다. 반복된 기능을 새 기능으로 계상하지 않는다.
- **Pretendard Regular/SemiBold.** 제목·본문·설명 구분과 줄바꿈을 직접 조절한다. 숫자는 별도 열/텍스트로 정렬하고 큰 주황색 항목 열은 간결한 항목명으로 대체한다.
- **한 흐름도에 주요 화면1~2개.** 전체 화면이 필요한 경우와 실제 조작 부분의 확대가 필요한 경우를 나눈다. 캡처 내용은 바꾸지 않으며 사용자가 볼 핵심 영역을 확대한다.
- **작성 흔적 제거.** ‘화면:9/16’, ‘운영본’, ‘원문/이용조건’ 반복 footer를 없앤다. 사진 자체의 출처 표시와 별도 출처 문서·노트는 유지한다.
- **API2종의 역할 설명.** 국문은 장소 검색·좌표·상세·사진, 무장애는 주차·접근·편의정보다. 빈 행을 삭제하고 실제 화면과 연결한다. 집중률/중심/연관 서비스는 표본 호출만 했으므로 실사용으로 추가하지 않는다.
- **기타 데이터는 활용과 화면으로 설명.** 통일부/보훈부 기본 후보, 기상청8시간 예보, 카카오 위치·길찾기를 대응한다. 불필요한 경고형 문단을 없앤다.
- **차별성3개 + 발전계획3단계.** 공동 일정/개인 기준의 분리, 조정 가능한 복귀 여유, 실제 저장으로 이어지는 제안이 현재 구현이다. 사용성 관찰→강원 정보 갱신→지역 실증은 앞으로 확인할 계획으로 구분한다.

## 내용 정정

- ‘초대받은 사람이 가입’ → **초대코드로 참여**: 체험 사용자도 가능하다.
- ‘저장 후 되돌리기’ → **비교·적용 후 저장, 저장 전 되돌리기**: 편집 중 조정 이력이다.
- `+119분→+192분`, 도보`30분→15분`은 동일 예시 일정의 추정 비교다. 실제 여행 성과나 교통 예측 정확도를 뜻하지 않는다.
- TourAPI 좌표는 이동 추정에, 운영·무장애 정보는 이용자가 방문 조건을 확인하는 데 활용한다. 무장애 자동 점수화나 현장 방문 인증은 주장하지 않는다.
