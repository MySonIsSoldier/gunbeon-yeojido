### 13쪽으로 작성하는 이유

첨부 작성용 PPTX는 **16:9, 기본 9쪽**입니다. 미리보기 PDF는 A4 가로 용지에 슬라이드를 배치하여 위아래 여백이 있지만, 작성용 PPTX의 실제 비율은 16:9입니다.

6번째 ‘서비스 핵심 기능별 흐름도’ 슬라이드에 **핵심 기능 최대 5개, 필요 시 해당 페이지 복사**가 명시되어 있습니다. 따라서 이 슬라이드를 5개 기능에 한 쪽씩 사용하면 기본 9쪽에 4쪽을 추가한 **총 13쪽**이 됩니다. 13쪽은 양식이 강제하는 총 페이지 수가 아니라, 허용된 복사 방식에 따른 이번 편집 선택입니다. 별도 총 페이지 상한은 확인한 양식에 없으며, 예선 제안서의 5쪽 규칙을 적용하지 않습니다.

## 실제 API 활용과 인증키

본문과 접수의 한국관광공사 활용 목록은 **국문 관광정보 서비스_GW, 무장애 여행 정보 2종**입니다. 국문 목록·검색·상세·사진·좌표는 장소 선택과 일정 작성에, 무장애 상세의 제공 필드는 주차·편의·동행 조건 확인에 활용합니다. 값이 없는 항목은 미확인으로 취급합니다.

- 개발 기간의 실제 호출 이력과 서비스 내부 활용을 함께 제시합니다. 단순 접근 시험만 한 집중률·중심·연관 API는 이번 실제 활용 목록에 추가하지 않습니다.
- 공사 파일데이터만 사용해서는 OpenAPI 필수 조건을 충족하지 않습니다. 장애 시 대체 자료와 mock 검사는 실호출 성공 증거와 구분합니다.
- 실제 사용한 API 신청자의 **인코딩·디코딩 인증키를 모두** 주최 측 지정 비공개 입력란에 제출합니다. 신청자가 다르면 해당 신청자의 키도 필요합니다. 기존 매뉴얼의 입력 화면은 최소 1쌍·최대 3쌍으로 안내하며, 실제 접수 화면의 최신 안내를 따릅니다.
- 같은 신청자의 공통 일반 인증키를 여러 승인 서비스에 사용하더라도, 서비스 목록은 실제 활용한 각 서비스를 선택합니다. 키 쌍을 서비스별로 임의 복제하지 않습니다.
- **API 키·OAuth Secret·개인 계정 비밀번호는 PPTX/PDF·이미지·공유 문서·GitHub에 넣지 않습니다.** 키가 들어간 URL·콘솔 화면도 캡처하지 않습니다.
- TourAPI 응답의 로컬 DB 저장에는 별도 신청 조건이 있습니다. 이번 서비스는 관광공사 원문 응답·사진을 운영 DB에 적재하지 않고 직접 작성한 일정과 장소 참조를 저장합니다.
- 권장 출처 문구는 `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩`입니다. 기관 CI/BI로 공식 운영 서비스처럼 보이게 하지 않습니다.

### 대표 API 운영계정 신청은 선택

최신 1차 안내와 키 가이드는 **대표 API 1개 운영계정 신청을 선택 사항**으로 안내합니다. 신청한다면 실제 활용 서비스 중 대표 1개를 팀당 한 번 선택하고, 서비스 URL이 준비된 상태에서 1차 제출 기한 내 진행합니다. 승인·반려 자체를 공모전 평가나 제출 가능 여부와 동일시하지 않습니다. 초기 자료의 예고를 근거로 필수 조건을 추가하지 않습니다. 신청 준비·실제 신청·승인은 각각 기록하며, 문서 작성만으로 신청한 것으로 표시하지 않습니다.

## 평가와 표현 기준

1차는 서비스 기획력 30점·서비스 완성도 30점·데이터 활용 적절성 20점·서비스 발전성 20점이며, 지역특화 가점은 2점입니다. 강원특별자치도 안의 복수 기초지자체를 묶는 특화가 허용됩니다. 최종 PT 배점이나 ②-2 구현 부문 조건을 섞지 않습니다. [공식 참가자 Notion](https://lowly-polyanthus-1fb.notion.site/2026-36b5dce406e380e0a3d1f80525667a11)

- 복귀 여유·도보·이동은 추정과 가정 범위를 밝힙니다. 실시간 교통 예측·군 복귀 보장으로 쓰지 않습니다.
- 공식 운영·예약 조건은 확인한 장소와 시점에 한해 설명합니다. 미확인을 이용 가능으로 바꾸지 않습니다.

- 제안서의 컨셉 이미지를 현재 구현 화면으로 사용하지 않습니다. 지역 소비·관광 활성화·참여 확산은 실제 측정하지 않았다면 기대효과나 향후 검증 계획으로 씁니다.
