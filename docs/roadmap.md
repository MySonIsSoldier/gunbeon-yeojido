## 검증과 배포 완료 기준

- `web/`에서 `npm run typecheck`, `npm test`, `npm run build` 및 변경 흐름의 브라우저/API 검사 결과를 기록한다.
- 키 없는 QA, 실연동, 실제 기기를 구분한다. 현재 작업의 테스트 수·성공·새 배포 버전을 미리 채우지 않는다.
- 기존 그룹 초대·공동 편집·개인 복귀 정보 분리와 계획→출타→완료→취소 흐름을 확인한다.
- 배포 시 GitHub 최종 SHA·Sites source SHA·실제 버전·D1 상태·공개 검증을 연결한다. 문서와 앱이 같은 버전을 설명해야 한다.
- 사용자 문의·증설 신청은 준비/발송/접수/승인을 구분한다. 요청 초안만으로 승인량 증가를 완료 처리하지 않는다.

## 제출 준비

현재 저장소의 공식 안내 확인 기록 기준이며, 변경 여부는 최종 제출 전에 확인한다.

- 웹은 접속 가능한 URL을 제출한다. 지정 기능설명서 PDF 1개는 10MB 이하, 대표 이미지 1장·상세 3~5장·핵심 기능 최대 5개를 준비한다.
- 실제 사용한 한국관광공사 OpenAPI 최소 1개 이상의 입력→활용→화면 근거를 만든다. 단순 인증 테스트만 한 API와 구분한다.
- 신청자 키는 제출 시스템의 지정 칸에만 입력한다. 문서·스크린샷·Git에 실제 키를 남기지 않는다.
- 지정 전용 테스트 계정 조건과 현재 임시 공통 비밀번호 입장을 대조하고 심사 접근을 확정한다.
- 최신 팀원/참가 정보, 필수 동의·이메일 인증, 제출 완료/접수 확인을 담당자와 마무리한다.
- 공식 자료에 없는 앱스토어 출시·영상·유료 도메인 조건을 임의로 추가하지 않는다.
