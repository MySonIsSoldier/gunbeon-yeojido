## API 선택·키·저장 정책

- 접수 목록에서는 **한국관광공사_국문 관광정보 서비스**, **한국관광공사_무장애 여행 정보**만 선택한다. 국문 응답의 사진을 사용하므로 별도 관광사진 API를 사용한 것으로 체크하지 않는다.
- 집중률·중심·연관 관광지는 시험 호출과 현재 서비스 통합을 구분해 선택에서 제외한다. 기상청·Kakao·통일부·보훈 자료는 기타 데이터다.
- 공공데이터포털 **마이페이지 첫 화면 → 개인 API 인증키**에서 Encoding/Decoding을 각각 복사한다. ‘인증키 발급현황’에는 인코딩만 표시된다. 동일하게 복사되면 사용자 제공 접수 안내에 따라 양쪽에 그대로 입력한다.
- 실제 사용한 신청자별 인증키를 최소 1쌍·최대 3쌍 입력한다. 한 신청자의 공통 인증키로 2종을 활용하면 서비스는 각각 선택하고 키 쌍은 해당 신청자의 것으로 입력한다.
- 대표 API 운영계정 신청은 **선택**이며 신청 시 대표 1개·팀당 1회다. 실제 신청·승인 상태만 기재한다. FAQ의 초기 운영계정 예고 문구보다 최신 1차 안내·제출 표·키 가이드의 선택 조건을 따른다.
- 주최 측은 실제 API 호출 이력과 서비스 내 활용을 확인한다. 원문 응답·사진을 운영 DB에 적재하지 않고 실호출·페이지 메모리 재사용과 장소 참조 저장을 유지한다. 원문 DB 저장에는 별도 신청 조건이 있다.
- 출처는 `출처: ⓒ한국관광공사` 등 기관명 텍스트로 밝힌다. 기관 CI/BI를 사용하거나 공사가 운영하는 서비스처럼 표시하지 않는다.

## 심사 기준과 설명 원칙

1차 배점은 서비스 기획력 30·완성도 30·데이터 활용 적절성 20·발전성 20이다. 지역특화 가점은 2점이며 강원 안의 접경 5군을 묶는 현재 범위가 해당 조건에 맞는다. 실제 가점 부여는 심사에 따른다.

복귀 여유는 거리·이동수단·입력 조건에 따른 참고 추정이며 실시간 교통·복귀 보장이 아니다. 접근성 정보는 제공 필드 확인이며 전체 관광지의 이용 가능 보장이 아니다. 직접 입력한 장소는 개인 계획에 저장되고 명시적으로 그룹에 포함할 수 있으므로 ‘모든 장소 좌표 미수집’이라고 쓰지 않는다. 공개 카드의 정확한 개인 시각·직접 입력 장소 제외를 설명한다. 사용자 실증이나 관광 소비 효과를 측정한 것으로 표현하지 않는다.
