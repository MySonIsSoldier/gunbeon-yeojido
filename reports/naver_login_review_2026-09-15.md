# 네이버 운영 로그인 연결과 검수 캡처

## 실행

- 시작 시 로컬 .env.local에 NAVER_CLIENT_ID/SECRET, AUTH_BASE_URL이 존재했고 Google ID/Secret은 없었다. 값은 로그·문서·Git에 기록하지 않았다.
- 운영 env revision2에는 소셜 설정이 없었다. 제공된 네이버 값과 공개 AUTH_BASE_URL만 추가하여 **revision3**으로 갱신했다. TourAPI·Kakao·테스트 Secret 보존.
- 기존 **Sites v18** source `b82711477d649f41896a7a32fbc07aca15f4aed1` 그대로 재배포. Deployment `appgdep_6aa8c3cbb14c8191a27b571dc48cd28e` **succeeded 2026-09-15 04:05:15UTC**, env revision3. 이번 작업에서 앱 코드·D1 스키마를 바꾸지 않았다.
- 운영 IAB에서 기존 로그인 계정에 네이버 연결이 이미 표시됨을 관찰했다. 해당 연결을 생성·삭제·변경하지 않았다. 정상 서비스 로그아웃 후 네이버 버튼을 클릭하여 같은 계정의 서비스 홈 복귀와 연결 상태를 확인했다. 서비스 비밀번호·체험 비밀번호 입력 없음.
- 기존 네이버 로그인·동의 세션이 있어 중간 화면은 생략되었다. 실제 신규 회원 생성/새 동의 검증·Google 실로그인·네이버 검수 승인은 이번에 수행하지 않았다.

## 산출물·검증

- [제출 안내](../output/naver-review/README.md), 실제 화면 PNG3개 및 설명 PDF3쪽. 개인정보 영역의 불투명 마스킹을 raster 단계에서 적용했다. 원본은 tmp/에만 보관하고 최종 PNG·PDF만 버전관리한다.
- `scripts/create_naver_review_pdf.py`: 로컬 캡처와 UI에서 읽은 마스킹 좌표를 입력으로 사용한다. 실제 설치 확인: Pillow12.3.0, ReportLab4.4.9, fonttools4.65.0, brotli1.2.0. 새 PC는 raw 개인정보 자료를 Git에서 가져오지 않으며, 이미 제공된 최종 파일은 그대로 사용할 수 있다.
- CUA fullPage 캡처가 배율/스티칭 문제를 보여 네이티브 viewport 스크린샷으로 다시 촬영했다. UI나 인증 상태를 합성하지 않았다.
- 최종 PDF3쪽을 모두 렌더링하여 글자·레이아웃·마스킹·사진 출처를 확인했다. PDF660,997bytes, PNG 각122,823/247,545/127,960bytes, 모두612×964px. PDF 본문에 계정 별명·아이디 없음 확인. 파일당5MB 미만, PDF1개 또는 PNG3개로 최대5개 조건 충족. 화면1 하단 자체 비밀번호 필드와 네이버 가입 동선을 설명으로 명확히 구분했다.
- 앱 소스 변경이 없어 단위/전체 브라우저 테스트를 재실행하지 않았다. 운영 네이버 로그인 실동작이 이번 검증의 근거다.

## Google 판단

사용자가 본 누락 도메인은 `ybuser.chatgpt.site`이다. 목록 추가와 Search Console 소유 확인·브랜드 검수는 분리한다. Google `openid` 기본 로그인은 검수 전 시험 경로가 있지만 실제 키/콘솔 저장은 아직 확인하지 않았다. 다른 사람의 승인된 도메인 문자열을 빌리거나 HTML 태그만으로 정식 브랜드 인증을 보장하지 않는다. [업데이트 안내](../docs/social-login-setup.md#도메인-확인과-일반-공개).

## 다음 행동

네이버 콘솔에서 적용 형태를 신규 회원가입으로 선택하고 PDF를 첨부해 검수 신청한다. 더 많은 개인정보 조회 권한이 설정되어 있는지 확인한다. 새 동의 화면 요청이 있으면 새로운 테스터 계정으로 추가 캡처한다. Google은 승인된 도메인 목록 등록 후 키 발급이 가능한지 확인하고 가능하면 기본 로그인부터 검증한다.
