# 일정 보기와 편집 분리 · 2026-09-15

## 제품 결정

여행을 눌렀을 때 편집 폼과 저장 버튼부터 보이는 진입을 없앴다. 홈·내 여행·그룹 모두 ‘일정 보기’로 시작하고, 고치려는 경우에만 상단 ‘일정 편집’을 연다. 개인 일정 편집 후 저장/취소는 읽기 화면으로 돌아온다. 빈 여행·날짜 미정도 열람할 수 있다.

보기 화면은 사진 창문, 여행명·지역·날짜, 장소 수·이동수단·동행자, 만남 장소, 방문 순서·예상 도착·체류·도보, 만남 장소로 돌아오는 예상 시각을 보여준다. 예약/신분증/운영 제한은 해당 장소에서 확인하며 방문 정보와 접을 수 있는 지도·시간 근거로 이어진다. 날짜를 넘기는 일정에는 날짜도 표시한다.

- 개인 복귀 계획은 저장한 출발시각과 해당 여행의 동행 조건만 사용한다. 현재 시각 카운트다운이나 다른 편집 화면의 조건을 상속하지 않는다.
- 그룹에는 개인 복귀 시각·여유를 표시하지 않는다. ‘내 여행에 담기’에서 개인 사본에 기준을 정한다. 기존 공유 확인·버전 충돌 검사는 유지한다.
- 현재 출타는 편집을 잠그고 ‘현재 출타 이어보기’를 제공한다. 완료 기록은 당시 계획임을 표시하며 ‘새 여행으로 가져오기’로 사본을 만든다.
- 장소를 못 불러오면 원래 순서의 자리표시자를 남긴다. 좌표·날짜·이동수단이 미확정인 경우 이동시간을 지어내지 않는다. 관광정보 조회 기능을 축소하지 않았다.

## 디자인 근거

흰 바탕과 간결한 조작을 유지하고 청록 CTA, 살구색 날짜 표식, 옅은 자연색 표지와 실제 여행 사진을 사용했다. 안전/주의/위험의 의미는 유지한다. 그룹 카드에는 사진과 대표 ‘일정 보기’를 두고 편집·사본·브리핑·삭제는 더보기로 정리한다. 작은 화면은 세로 일정표, 데스크톱은 일정과 복귀 정보의 두 열이다.

공식 사례는 UI 복제 대신 다음 원칙을 참고했다.

- [트리플 일정 공유·편집](https://triple.guide/articles/8e26647d-9e7b-4346-8517-4945ced97bb8): 함께 볼 일정과 편집 동작을 구분한다.
- [Wanderlog](https://wanderlog.com/): 일정과 지도, 구간 이동 정보를 연결한다.
- [Airbnb 여행 화면](https://news.airbnb.com/en-uk/2025-summer-release-now-you-can-airbnb-more-than-an-airbnb): 만든 여행에서는 날짜와 다음 행동을 우선한다.

## 구현·검증

`TripOverview`와 `itineraryView`는 읽기 전용 투영이다. 열기만으로 `settings`, Entry 또는 서버 상태를 변경하지 않는다. TourAPI 참조 복원 대상에 열람 중인 일정을 추가했다. 그룹 편집은 원래 GroupPlan ID/version을 유지하고 저장 응답으로 읽기 화면을 갱신한다.

새 지도 폭에서 서로 가까운 44px 장소 번호가 겹쳐 터치를 막는 것을 발견했다. 지도 좌표·SDK 호출 수는 그대로 두고 화면 내 라벨만 간격 조정한다. 지도 밖 장소를 화면 안으로 끌어들이지 않는다. 이동된 버튼의 원래 SDK 래퍼가 투명한 터치 장애물이 되지 않도록 포인터 이벤트를 구분했다. DOMRect의 프로토타입 접근자도 검사한다. [Kakao CustomOverlay·idle 공식 문서](https://apis.map.kakao.com/web/documentation/)

- TypeScript·단위99개·최종 빌드 통과.
- 읽기/편집 단위 검사: 과거 날짜·익일 귀환·원본 불변·그룹 개인 조건 분리·누락 좌표/이동수단·빈 일정, 지도 라벨 충돌과 DOMRect.
- Chrome153 / Chromium151: 360·430·1440px 총6환경. 열람 무변경, 수정/저장·취소, 누락 장소 순서, 날짜 없는 빈 일정, 가로 넘침·런타임 오류 검사 통과. [증빙](qa/itinerary-2026-09-15/viewports.json)
- Chromium 그룹·출타 잠금·여유 조정 기존 흐름 통과. 키 없는 전체 개인 코스/브리핑360·1440px 통과. `/guide` 23개 화면 리소스360·1440px 확인.
- 물리적 iOS/Android와 이 PC에 없는 Edge는 새로 검사하지 않았다. 정상 로그인 구현과 Google/Naver 실제 동의 성공은 구분한다.

실제 TourAPI 수신·Kakao 타일/핀 선택·새로고침 후 동일 순서 복원·부모 브리핑·공유 카드·의도적 조회 실패를 포함한 360px 실연동 검사10항목 통과. [실연동 증빙](qa/itinerary-2026-09-15/live-browser.json). 자동 검사에서 기본 장소만으로도 코스가 구성될 수 있어 누락 참조 검사를 명시적 합성 ID로 고쳤다. PR26과 최종 공개 반영은 `docs/handoff.md`에 기록한다.

## 사용자 시나리오

1. 홈의 예정된 여행 → 일정 보기. 입력창 없이 여행 날짜·장소·시간을 읽는다.
2. 일정 편집 → 체류시간/날짜/장소 변경 → 변경사항 저장. 새 일정표로 돌아와 변경 결과를 확인한다.
3. 그룹 → 그룹 여행 일정 보기. 함께 보는 순서만 확인하고 개인 계획은 ‘내 여행에 담기’에서 만든다.
4. 떠나는 날에는 출타 시작. 현재 출타에서는 실시간 여유를 보고 계획은 잠근다.
5. 다녀온 기록은 내 여행 → 여행 기록. 제목으로 당시 일정 열람, 더보기로 기록 수정·계획 복원, 새 여행으로 가져오기로 사본 작성.

공개 `/guide`와 README에 실제 합성 예시 화면을 추가했다. 신규 PC 검사는 `web/`에서 `npm run test:itinerary`; Chrome 설치가 없으면 기본 Chromium을 쓴다. 소셜 로그인은 [발급·설정 안내](../docs/social-login-setup.md)를 따른다.
